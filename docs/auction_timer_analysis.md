# 실시간 경매 타이머 기능 분석 및 설계 보고서 (최종 업데이트)

## 1. 개요
본 문서는 실시간 경매 시스템의 타이머 및 입찰 로직에 대한 최종 구현 상태를 기술합니다. 클라이언트-서버 간의 시간 동기화 문제를 해결하고, 모든 유저에게 일관된 경매 상태를 제공하기 위한 설계 결정 사항을 포함합니다.

## 2. 핵심 요구사항 및 구현 현황

| 요구사항 | 구현 상태 | 상세 내용 |
| :--- | :--- | :--- |
| **1. 참여 인원 제한** | 완료 | 주최자 1명 + 리더 최소 2명 접속 시에만 경매 시작 가능 |
| **2. 입찰 권한 제어** | 완료 | 주최자를 제외한 리더 권한 유저만 입찰 가능 |
| **3. 타이머 시작** | 완료 | 경매 시작 시 현재 시간 기준 +10초 타이머 설정 |
| **4. 5초 초과 시 미갱신** | 완료 | 남은 시간이 5초 초과일 경우 입찰해도 타이머가 연장되지 않음 |
| **5. 5초 이하 시 갱신** | 완료 | 남은 시간이 5초 이하일 경우 입찰 시점부터 5초 후로 갱신 |
| **6. 이벤트 일관성** | 완료 | 모든 유저에게 동일한 타이머 상태 송출 (연장 시에만 시간 정보 포함) |

## 3. 주요 설계 및 기술적 해결 방안

### 3.1. 서버 시간 동기화 (Clock Synchronization)
*   **문제**: 클라이언트마다 로컬 시간이 달라 타이머가 다르게 표시되거나 입찰 시 타이머가 튀는 현상 발생.
*   **해결**: Firebase RTDB의 `.info/serverTimeOffset`을 구독하여 `serverTimeOffset`을 산출. 모든 시간 계산은 `Date.now() + serverTimeOffset`을 통한 **추정 서버 시간**을 기준으로 수행.

### 3.2. 조건부 이벤트 브로드캐스트 (Conditional Event Broadcast)
*   **문제**: 입찰자가 보낸 이벤트에 포함된 종료 시간이 다른 유저들의 로컬 시간과 충돌하여 타이머가 부정확하게 갱신됨.
*   **해결**: 
    *   타이머가 **실제로 연장된 경우**에만 이벤트 데이터에 `timerEndsAt`을 포함.
    *   타이머가 연장되지 않은 입찰은 시간 정보를 생략하여, 다른 유저들이 기존의 정확한 타이머 상태를 유지하도록 보장.

### 3.3. 낙관적 업데이트 및 스무딩 (Optimistic UI & Smoothing)
*   **낙관적 업데이트**: 입찰 즉시 추정 서버 시간을 기반으로 타이머를 미리 갱신하여 인지 지연 시간을 최소화.
*   **스무딩**: 서버 응답 수신 시 클라이언트 타이머와 오차가 200ms 이내라면 UI 갱신을 무시하여 떨림 현상 방지.

## 4. 코드 구조 리팩토링

*   **상수화**: `BID_INCREMENT`, `AUCTION_DURATION_MS` 등 모든 매직 넘버를 `auctionTimings.ts`로 추출하여 관리.
*   **보안 규칙**: `firestore.rules`에서 서버 시간을 기준으로 타이머 갱신 조건을 최종 검증하여 클라이언트 조작 방지.

## 5. 결론
현재 시스템은 실시간 입찰의 핵심인 **정확성**과 **일관성**을 확보했습니다. 특히 서버 시간 동기화와 조건부 이벤트 전송 구조는 네트워크 환경이 다른 유저들 사이에서도 공정한 경매를 가능하게 합니다.
