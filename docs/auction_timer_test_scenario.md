# 실시간 경매 타이머 기능 테스트 시나리오

## 1. 목표

수정된 실시간 경매 타이머 기능이 사용자 요구사항에 따라 정확하게 동작하는지 검증하고, 특히 경매 시작 시 참여 인원 검증 및 입찰 시 타이머 갱신 로직이 올바르게 작동하는지 확인합니다.

## 2. 테스트 환경

*   **환경**: Firebase 기반 개발/스테이징 환경
*   **클라이언트**: 웹 브라우저 (최소 3개 이상 필요)
*   **역할**: 주최자 (Organizer), 리더 1 (Leader 1), 리더 2 (Leader 2)

## 3. 테스트 대상 기능

*   경매 시작 시 참여 인원 검증 (최소 3명 이상)
*   경매 시작 타이머 (10초)
*   리더 권한 유저의 입찰 가능 여부
*   입찰 시 타이머 갱신 로직 (5초 임계값)
    *   남은 시간 5초 초과 시 타이머 미갱신
    *   남은 시간 5초 이하 시 입찰 시점 기준 5초 후로 타이머 갱신
*   경매 종료 및 낙찰/유찰 처리
*   타이머 동기화 및 신뢰성

## 4. 테스트 시나리오

다음 표는 각 테스트 케이스에 대한 상세한 절차와 예상 결과를 설명합니다.

| 테스트 케이스 ID | 테스트 항목 | 테스트 절차 | 예상 결과 |
|---|---|---|---|
| **TC-001** | **경매 시작 시 참여 인원 검증 (실패)** | 1. 주최자 1명만 방에 입장한다.<br>2. 주최자가 선수 추첨을 시도한다. | 경매 시작 실패 메시지 (`경매를 시작하려면 주최자 1명과 최소 2명의 리더가 필요합니다.`)가 표시된다. |
| **TC-002** | **경매 시작 시 참여 인원 검증 (실패)** | 1. 주최자 1명, 리더 1명만 방에 입장한다.<br>2. 주최자가 선수 추첨을 시도한다. | 경매 시작 실패 메시지 (`경매를 시작하려면 주최자 1명과 최소 2명의 리더가 필요합니다.`)가 표시된다. |
| **TC-003** | **경매 시작 시 참여 인원 검증 (성공)** | 1. 주최자 1명, 리더 1명, 리더 2명이 방에 입장한다.<br>2. 주최자가 선수 추첨을 시도한다.<br>3. 주최자가 경매 시작 버튼을 클릭한다. | 선수 추첨이 성공하고, 경매가 시작되며 10초 타이머가 모든 클라이언트(주최자, 리더 1, 리더 2)에 동기화되어 표시된다. |
| **TC-004** | **리더 권한 유저 입찰 가능 여부** | 1. TC-003의 경매 시작 상태에서, 리더 1이 입찰을 시도한다.<br>2. 주최자가 입찰을 시도한다. | 리더 1의 입찰은 성공하고, 주최자의 입찰은 실패한다 (입찰 버튼 비활성화 또는 에러 메시지). |
| **TC-005** | **타이머 갱신 로직 (5초 초과 시 미갱신)** | 1. TC-003의 경매 시작 상태에서, 타이머가 10초에서 6초를 가리킬 때 (남은 시간 5초 초과) 리더 1이 입찰한다.<br>2. 모든 클라이언트에서 타이머 변화를 관찰한다. | 타이머가 갱신되지 않고 계속해서 카운트다운된다. (예: 6초 -> 5초 -> 4초) |
| **TC-006** | **타이머 갱신 로직 (5초 이하 시 갱신)** | 1. TC-003의 경매 시작 상태에서, 타이머가 5초를 가리킬 때 (남은 시간 5초 이하) 리더 1이 입찰한다.<br>2. 모든 클라이언트에서 타이머 변화를 관찰한다. | 타이머가 입찰 시점으로부터 5초 뒤로 갱신되어 표시된다. (예: 5초 -> 5초, 4초 -> 5초) |
| **TC-007** | **타이머 갱신 로직 (연속 입찰)** | 1. TC-003의 경매 시작 상태에서, 타이머가 5초를 가리킬 때 리더 1이 입찰한다.<br>2. 타이머가 3초를 가리킬 때 리더 2가 입찰한다.<br>3. 모든 클라이언트에서 타이머 변화를 관찰한다. | 리더 1의 입찰로 타이머가 5초로 갱신되고, 이어서 리더 2의 입찰로 다시 5초로 갱신된다. (항상 입찰 시점 기준 5초 후로 설정) |
| **TC-008** | **경매 종료 및 낙찰 처리** | 1. TC-003의 경매 시작 상태에서, 아무도 입찰하지 않아 타이머가 0초가 될 때까지 기다린다.<br>2. 경매 종료 후 낙찰 처리 및 알림을 확인한다. | 타이머가 0초가 되면 경매가 종료되고, 최고 입찰자(없다면 유찰)에게 낙찰 처리되며, 모든 클라이언트에 경매 종료 및 결과 알림 메시지가 표시된다. |
| **TC-009** | **클라이언트-서버 시간 동기화** | 1. TC-003의 경매 시작 상태에서, 클라이언트 PC의 시간을 수동으로 변경해본다 (예: 1분 빠르게/느리게).<br>2. 타이머의 동작을 관찰한다. | 클라이언트 PC의 시간 변경과 관계없이 서버 시간 기준으로 동기화된 타이머가 표시된다. (약간의 지연은 있을 수 있으나, 큰 오차 없이 동기화 유지) |
| **TC-010** | **경매 중 리더 이탈 및 재참여** | 1. TC-003의 경매 시작 상태에서, 리더 1이 방을 나간다.<br>2. 리더 1이 다시 방에 입장한다.<br>3. 경매 타이머 및 입찰 상태가 정상적으로 동기화되는지 확인한다. | 리더 1이 방을 나갔다가 다시 들어와도 현재 진행 중인 경매 타이머와 입찰 상태가 정상적으로 표시된다. |

## 5. 테스트 수행 가이드

*   각 테스트 케이스는 독립적으로 수행될 수 있도록 초기 상태를 설정합니다.
*   타이머의 정확한 동작을 확인하기 위해 여러 클라이언트(브라우저 탭 또는 다른 기기)에서 동시에 접속하여 관찰하는 것을 권장합니다.
*   특히 타이머 갱신 로직(TC-005, TC-006, TC-007)은 시간 임계값에 맞춰 정확한 시점에 입찰을 시도해야 합니다. 필요시 개발자 도구의 네트워크 탭을 활용하여 입찰 요청 시점과 서버 응답을 확인합니다.
*   예상 결과와 다른 동작이 발생할 경우, 상세한 로그와 스크린샷을 첨부하여 버그 리포트를 작성합니다.
