# 실시간 경매 타이머 및 애니메이션 기능 테스트 시나리오 (최종 업데이트)

본 문서는 수정된 실시간 경매 타이머 기능과 Motion One으로 리팩토링된 선수 추첨 애니메이션의 정상 동작을 검증하기 위한 테스트 시나리오를 제공합니다.

## 1. 참여 인원 검증 테스트

| ID | 테스트 항목 | 절차 | 예상 결과 |
| :--- | :--- | :--- | :--- |
| TC-01 | 인원 부족 시 경매 시작 불가 | 주최자 1명, 리더 1명만 접속한 상태에서 선수 추첨 시도 | "리더가 최소 2명 필요합니다" 에러 메시지 표시 및 추첨 실패 |
| TC-02 | 인원 충족 시 경매 시작 가능 | 주최자 1명, 리더 2명 이상 접속한 상태에서 선수 추첨 시도 | 정상적으로 선수 추첨 완료 및 경매 대기 상태 진입 |

## 2. 타이머 갱신 로직 테스트 (8초 규칙)

| ID | 테스트 항목 | 절차 | 예상 결과 |
| :--- | :--- | :--- | :--- |
| TC-03 | 8초 초과 시 타이머 유지 | 남은 시간이 9초인 시점에 리더가 입찰 시도 | 입찰은 성공하나, 타이머는 8초로 줄어들지 않고 기존 시간 유지 |
| TC-04 | 8초 이하 시 타이머 갱신 | 남은 시간이 3초인 시점에 리더가 입찰 시도 | 입찰 성공 즉시 타이머가 8초로 갱신됨 |
| TC-05 | 연속 입찰 시 타이머 리셋 | 남은 시간 3초에 입찰하여 8초가 된 직후(7.5초 남음) 다른 리더가 재입찰 | 타이머가 다시 8초로 갱신됨 (누적이 아닌 리셋) |

| ID | 테스트 항목 | 절차 | 예상 결과 |
| :--- | :--- | :--- | :--- |

| TC-07 | 낙관적 업데이트 반응성 | 리더 A가 3초 남은 시점에 입찰 버튼 클릭 | 서버 응답 전 클라이언트 UI에서 즉시 8초로 변경됨 |
| TC-08 | 서버 시간 동기화 | 로컬 시간이 1분 느린 리더가 입찰 시도 | 추정 서버 시간을 기준으로 정확히 8초 뒤에 종료되는 타이머 설정 |

## 5. 선수 추첨 애니메이션 테스트 (Motion One 기반)

| ID | 테스트 항목 | 절차 | 예상 결과 |
| :--- | :--- | :--- | :--- |
| TC-11 | 애니메이션 시작 및 종료 | 선수 추첨 시작 버튼 클릭 후 애니메이션 완료까지 관찰 | "추첨 중..." 메시지 표시 후 룰렛이 부드럽게 회전, 최종 선수 확정 후 "추첨 완료!" 메시지 표시 및 종료 효과 발생 |
| TC-12 | 애니메이션 부드러움 | 다양한 네트워크 환경 및 기기에서 애니메이션 관찰 | 끊김 없이 부드럽게 동작하며, CPU/GPU 사용량이 과도하게 증가하지 않음 |
| TC-13 | `useReducedMotion` 적용 | 시스템 설정에서 "움직임 줄이기" 옵션 활성화 후 애니메이션 실행 | 애니메이션 속도가 느려지거나, 일부 복잡한 효과(파티클 등)가 생략되어 표시됨 |
| TC-14 | 최종 선수 표시 정확성 | 애니메이션 종료 후 표시되는 선수 정보 확인 | `targetPlayer`로 지정된 선수의 이름, 티어, 포지션이 정확하게 표시됨 |
| TC-15 | 파티클 및 샤인 효과 | 애니메이션 종료 시 파티클 및 샤인 효과 관찰 | `shouldReduceMotion`이 `false`일 때, 최종 선수 확정 시 화려한 파티클 및 샤인 효과가 부드럽게 나타났다 사라짐 |
