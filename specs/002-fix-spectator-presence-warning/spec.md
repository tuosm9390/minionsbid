# 기능 명세서: 관전자 접속 이탈 경고 수정

**기능 브랜치**: `002-fix-spectator-presence-warning`  
**작성일**: 2026-03-24  
**상태**: 초안  
**입력**: 사용자 설명: "관전자 링크를 통해 입장하면 팀장 전체 접속한 이후에도 연결끊김 경고가 표시되는데 이 부분 분석해서 해결해줘."

## 확인 사항

### 2026-03-24 세션
- Q: 초기 데이터 로딩 중 연결 경고 처리 방식 → A: 첫 실시간 데이터가 도착할 때까지 중립적인 로딩 상태를 표시함.
- Q: 관전자 자신의 네트워크 단절 시 처리 → A: 팀장 이탈 경고와 구분되는 별도의 UI를 표시하며, 문구는 "연결 확인 중..."으로 설정함.
- Q: 관전자 접속 수 제한 및 알림 여부 → A: 인원 제한 없이 허용하되, 시스템 한계 근접 시 주최자에게 경고를 표시함.
- Q: 연결 상태 업데이트 주기 및 최적화 → A: Firebase 기본 실시간(Real-time) 업데이트를 유지함.
- Q: 관전자 화면의 '팀장 접속 현황' 상세 정보 노출 수준 → A: 현재와 동일하게 팀장 이름/팀명 및 접속 여부만 표시함.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 관전자가 잘못된 경고 없이 경매 시청 (우선순위: P1)
관전자가 관전자 링크를 사용하여 경매방에 입장합니다. 팀장이나 주최자가 아니더라도 모든 팀장의 실시간 접속 상태를 확인할 수 있어야 합니다. 모든 팀장이 접속한 상태라면 "연결 끊김" 경고가 표시되지 않아야 합니다.

**우선순위 이유**: 관전자 경험에 결정적입니다. 잘못된 경고는 관전자가 경매 진행 상황을 보는 것을 방해하고 방의 실제 상태에 대해 혼란을 줍니다.

**독립 테스트**: 모든 팀장이 접속된 활성 상태의 방에 비밀 모드로 관전자 링크를 열어 테스트할 수 있습니다. 경매 보드가 "연결 끊김" 오버레이 없이 보여야 합니다.

**수락 시나리오**:
1. **Given** 모든 팀장이 경매방에 접속된 상태일 때, **When** 관전자가 링크를 통해 입장하면, **Then** 100ms 이내에 중립 로딩 UI가 사라지고 경매 보드가 보여야 합니다.
2. **Given** 한 명 이상의 팀장이 접속되지 않았을 때, **When** 관전자가 입장하면, **Then** "팀장 접속 대기 중" 오버레이가 올바르게 표시되어야 합니다.
3. **Given** 관전자가 시청 중 팀장의 연결이 끊겼을 때, **When** 경매가 진행 중이라면, **Then** 200ms 이내에 "연결 끊김" 오버레이가 나타나야 합니다.

---

### 예외 케이스
- **초기 로딩 지연**: 첫 실시간 데이터 수신 전까지 "데이터 확인 중..." 문구와 픽셀 로딩 스피너를 포함한 중립적인 로딩 상태를 표시하여 경고창 깜빡임을 방지함.
- **자신의 네트워크 단절**: 관전자 본인의 인터넷 연결이 끊긴 경우, "연결 확인 중..." 문구와 함께 `bg-minion-blue/20` 배경의 전용 안내를 표시하여 팀장 이탈(빨간색)과 시각적으로 구분함.
- **다수 관전자 접속**: Firebase RTDB는 수천 명의 동시 구독자를 지원하므로 별도의 인원 제한은 두지 않으나, 시스템 모니터링을 위해 등록된 세션(주최자+팀장) 기준으로 관리함.
- **부분적 장애**: RTDB(접속 정보)는 정상이나 Firestore(경매 데이터) 수신이 지연될 경우, 보드의 틀은 유지하되 데이터 영역에 스켈레톤 UI를 표시함.
- **상태 복구**: 네트워크 단절 후 복구 시, 로컬 상태(`isLocalConnected`)가 true로 전환되는 즉시 오버레이를 제거함.

## 요구사항 *(필수)*

### 기능적 요구사항
- **FR-001**: 시스템은 `VIEWER` 권한을 가진 사용자가 방의 모든 참여자 접속 상태를 구독할 수 있도록 허용해야 함.
- **FR-002**: 시스템은 팀장의 실제 접속 여부에 따라 `VIEWER` 사용자의 `allConnected` 상태를 실시간으로 업데이트해야 함.
- **FR-003**: 시스템은 모든 필수 팀장이 접속한 경우 `VIEWER` 사용자에게 연결 끊김 경고 오버레이를 표시하지 않아야 함.
- **FR-004**: 시스템은 `VIEWER` 사용자가 자신의 접속 정보를 등록하지 않는 기존 동작을 유지하여 불필요한 부하를 방지해야 함.
- **FR-005**: 시스템은 데이터베이스에서 첫 접속 데이터를 받기 전까지 중립적인 로딩 상태를 제공해야 함. (구성: 반투명 검은색 배경, 픽셀 스피너, "접속 현황 확인 중..." 텍스트)
- **FR-006**: 시스템은 관전자 자신의 네트워크 단절을 감지했을 때, 전용 안내 UI를 표시해야 함. (문구: "연결 확인 중...", 배경: `bg-minion-blue/20` 틴트)
- **FR-007**: 시스템은 등록된 참여자(주최자+팀장) 수가 80명 도달 시 주최자에게 "시스템 부하 경고" 배너를 표시하고, 70명 이하로 하락 시 자동으로 해제함(Hysteresis).
- **FR-008**: 시스템은 관전자의 접속 상태 동기화를 위해 Firebase RTDB의 실시간 스트리밍 업데이트 방식을 유지해야 함.
- **FR-009**: 동시 접속자 모니터링(FR-007)은 FR-004 원칙에 따라 '등록된 참여자'만 집계하며, 관전자는 집계 대상에서 제외함.

### 핵심 엔티티 *(데이터 관련 기능인 경우 포함)*
- **접속 상태 (Presence)**: 특정 경매방에서 사용자의 실시간 연결 상태를 나타냄. 주요 속성: `teamId`, `role`, `connectedAt`.
- **경매방 (Auction Room)**: 경매가 이루어지는 공유 공간. 경매 진행을 위해 특정 수의 팀장이 "접속"되어 있어야 함.

## 성공 기준 *(필수)*

### 측정 가능한 결과
- **SC-001**: 모든 팀장이 접속된 방에 입장한 관전자의 100%가 100ms 이내에 중립 로딩을 거쳐 경매 보드를 봄.
- **SC-002**: 팀장의 접속 상태가 변경될 때 관전자는 데이터 수신 후 50ms 이내에 UI 업데이트를 반영함 (전체 네트워크 지연 포함 200ms 목표).
- **SC-003**: 관전자 클라이언트의 쓰기 시도가 0건임을 Firebase 보안 규칙 로그 또는 에뮬레이터 검증을 통해 확인함.
